# 设备管理模块说明

设备列表提供「设备名称 / 设备编号 / 所属部门 / 状态 / 创建日期区间」五个后端筛选条件，并解决筛选后翻页、查看详情再返回时条件丢失的问题。

## 一、文件清单

### 后端（`jeecg-system-biz`）

| 文件 | 说明 |
| --- | --- |
| `org/jeecg/modules/device/entity/Device.java` | 设备实体，对应表 `device_info` |
| `org/jeecg/modules/device/mapper/DeviceMapper.java` | MyBatis-Plus Mapper |
| `org/jeecg/modules/device/service/IDeviceService.java` | Service 接口 |
| `org/jeecg/modules/device/service/impl/DeviceServiceImpl.java` | Service 实现 |
| `org/jeecg/modules/device/controller/DeviceController.java` | 接口：分页查询 / 增删改 / 详情 |

### 前端（`frontend/src`）

| 文件 | 说明 |
| --- | --- |
| `views/device/index.vue` | 设备列表（查询区 + 表格 + 条件持久化） |
| `views/device/DeviceDetail.vue` | 设备详情页（独立路由） |
| `views/device/device.api.ts` | 列表/详情/增删改接口封装 |
| `views/device/device.data.ts` | 列定义、状态枚举、新增/编辑表单 |
| `views/device/components/DeviceModal.vue` | 新增/编辑弹窗 |
| `router/routes/modules/device.ts` | 路由，列表页开启 `keepAlive` |

### 建表 / 菜单脚本

- SQL Server：`db/sqlserver/device_info.sql`、`db/sqlserver/device_menu.sql`
- MySQL：`backend/db/device_info.sql`（含建表与菜单，可直接在初始化库执行）

后台菜单模式（默认 `PermissionModeEnum.BACK`）下，需要执行菜单脚本后才能在导航看到「设备管理」；
切到前端菜单模式（`ROUTE_MAPPING`）时，静态路由 `router/routes/modules/device.ts` 会自动生效。

## 二、筛选条件如何走后端

列表接口 `GET /device/deviceInfo/list` 使用 JeecgBoot 的 `QueryGenerator` 在数据库侧过滤后再分页，参数：

| 前端参数 | 后端字段 / 规则 |
| --- | --- |
| `deviceName` | `device_name`，全模糊 LIKE |
| `deviceCode` | `device_code`，全模糊 LIKE |
| `sysOrgCode` | `sys_org_code`，精确匹配 |
| `status` | `status`，精确匹配（含 `0-闲置`） |
| `createTime_begin` | `create_time >=`，传 `yyyy-MM-dd`，后端自动补 `00:00:00` |
| `createTime_end` | `create_time <=`，传 `yyyy-MM-dd`，后端自动补 `23:59:59` |
| `pageNo` / `pageSize` | 分页参数 |

前端不存在“只过滤当前页数据”的逻辑，每次翻页、查询都携带上述参数请求后端。

## 三、条件如何保留

1. **翻页 / 查看详情再返回（主流程）**：列表路由 `DeviceList` 的 `ignoreKeepAlive: false`，组件 `defineOptions({ name: 'DeviceList' })` 与路由 name 一致。翻页或进入详情后列表页被 keepAlive 缓存，返回时表单条件、当前页码、选中状态原样保留，不会重复请求。
2. **新开详情页 / 刷新后再返回（兜底）**：点击「详情」时，会把当前条件和表格真实页码（`deviceName/deviceCode/sysOrgCode/status/beginDate/endDate/pageNo`）透传到详情路由。详情页在没有浏览器历史时返回列表，会把这些参数写回列表 URL；列表首次加载时 `restoreFromRoute()` 读取 URL，还原表单并用原条件、原页码请求后端。
3. 列表布局中组件使用 `:key="route.fullPath"`，翻页时若频繁改写列表 URL 会导致整页重建，所以正常查询/翻页不改 URL、只靠 keepAlive 保留状态；URL 仅用于第 2 点的兜底恢复。

## 四、重置按钮

`handleReset` 一次性清空：名称、编号、部门、状态、日期范围，并把页码回到第 1 页，同时清掉详情回退可能写入的 URL 参数，然后以空条件重新请求后端；不会只重置某一个控件或只清前端展示。

## 五、联调步骤

1. 在 SQL Server 中执行 `device_info.sql`；后台菜单模式下再执行 `device_menu.sql`（或在「系统管理-菜单管理」手工配置，组件路径分别填 `device/index`、`device/DeviceDetail`）。
2. 重启后端、前端，以 `admin/123456` 登录，访问 `/device/list`。
3. 组合条件查询 → 翻页 → 点「详情」→ 点「返回」，确认条件与页码仍在；点「重置」，确认全部条件被清空并回到第 1 页。
